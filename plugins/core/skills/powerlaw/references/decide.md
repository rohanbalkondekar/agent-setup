# Decide

Help the user choose and move. Default to a short recommendation, not an interview or a scoring spreadsheet.

## Find the smallest sufficient decision

- State the choice, desired outcome, and any non-negotiable constraints. Use the context already supplied. Ask only for missing information that could change the recommendation or its authorization; otherwise state a reasonable assumption.
- Separate a reversible, low-cost choice from one with costly consequences. Check who is affected, what reversal would actually take, and who owns the decision. A technical rollback does not undo a public commitment, lost data, or harm to another person.
- Define what is good enough before comparing options. Eliminate options that fail required criteria. If none qualify, say so and suggest the smallest way to find or create a viable option; do not quietly lower the requirements.
- For a routine reversible choice, recommend the simplest qualifying option. If two options are effectively tied, use an explicit default such as lower switching cost or an existing convention. Do not invent a meaningful difference to justify the choice.
- For a material unknown, name the fact that could change the choice and the cheapest useful check. Suggest a timebox proportionate to the stakes. At its end, decide if the evidence is sufficient, or name the unresolved blocker and who can resolve it. A deadline does not turn missing safety evidence into permission.
- When further comparison is unlikely to change the recommendation, stop. Distinguish repeated comparison from a genuine unknown; do not dismiss a specific unresolved risk as overthinking.

## Keep the effort proportionate

Use these lenses only when they help; do not explain all of them in every answer:

- **Satisficing:** stop looking once an option meets the stated requirements and the downside is acceptable. Required checks still apply.
- **40/70 rule:** an optional reminder that both premature action and endless information gathering have costs. Do not manufacture percentages, confidence scores, or a universal information threshold. State what is known, what is missing, and whether that gap matters.
- **Buridan's donkey:** when acceptable options are effectively equivalent, a transparent tie-break can end unproductive comparison. This does not apply when material differences remain unknown.
- **Regret minimization:** when values or a lost opportunity drive the choice, ask which trade-off the user would most regret and what small experiment could reduce that uncertainty. Do not assume future feelings or make regret the only criterion.
- **10/10/10:** when immediate discomfort dominates, briefly compare short-, medium-, and long-term effects. Use horizons that fit the decision; do not predict feelings or require three forecasts for a trivial choice.

For a consequential or hard-to-reverse choice, give a conditional recommendation and the smallest useful validation or review. Keep required approvals and specialist review. Never use these shortcuts to bypass legal, health, financial, safety, security, or other material constraints.

A recommendation does not authorize action. Do not send messages, spend money, publish, delete, or make commitments on the user's behalf without the required authorization. Continue authorized preparation while an approval is pending.

For a recurring choice, suggest a reusable default with an exception condition when that would save effort. Do not install a policy or automation merely because you recommended it.

## Return

Usually a few lines are enough:

- **Choose:** the recommendation and the main trade-off.
- **Uncertainty:** the material assumption or fact that could change it, if any.
- **Next:** one concrete action, including any required confirmation.
- **Revisit:** a specific trigger when useful, such as failed acceptance criteria or new evidence. Do not reopen the choice merely because another plausible option appears.

No mandatory decision log, extra framework, or follow-up meeting. For an irreversible decision that needs a record, use the project's existing convention.

## Synthetic examples

**`$powerlaw decide: Two local report layouts both show all required fields. I can switch in five minutes, but keep comparing them.`**

Use an existing layout convention if there is one; otherwise use the first qualifying layout as a tie-break. Both meet the requirements and switching is cheap. Start with one sample report. Revisit only if a required field is hard to find.

**`$powerlaw decide: Should we replace a shared service this week? The alternative is faster, but restore testing and data retention review are unfinished.`**

Keep the current service for now. Speed does not resolve the missing restore and retention evidence. Next, complete an isolated restore test and get the responsible owner's review; recommend a migration only if the required checks pass, with approval before execution.

**`$powerlaw decide: Every week I spend twenty minutes choosing between equivalent internal document templates.`**

Use the team's existing template by default when it meets the document's requirements. Make an exception only for a missing required section or an audience requirement. Start the next draft with that default; no automation is needed.
